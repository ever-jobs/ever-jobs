## 1. Problem statement

Ever Jobs reaches Workday boards only through the generic `source-ats-workday`
adapter, which needs a caller-supplied `companySlug` in the adapter's compound
`{tenant}:{wdNumber}:{site}` form. Nobody outside the codebase knows those
slugs (they are not the company domain: Northrop Grumman is `ngc:1:…`, RTX is
`globalhr:5:REC_RTX_Ext_Gateway`, Snap is `snapchat:1:snap`), so the default
fan-out never touches the large US employers that run their careers sites on
Workday — exactly the employers that hire software, AI and data **interns and
new grads** at scale, which is what the owner wants the downstream consumer
(ever-hust) to cover.

## 2. Scope

53 company plugins `source-company-<key>`, each a registry-delegating wrapper
around `Site.WORKDAY` generated by Spec 1735, with its board(s) verified live
on 2026-09-24 (one listing request per board, <= 1 req/s, honest UA). One
plugin (Visa) delegates to two boards, early careers first.

## 3. Non-goals

- No Workday adapter change beyond the review follow-ups (T6, T8; Spec 1735
  §4.6): the keyword now reaches Workday as `searchText` (`''` in list mode)
  and detail enrichment is sequential (1 in flight, 250–500 ms apart).
  Pagination (20 per page, 1–2 s between pages) and one detail request per
  enriched posting are inherited unchanged — see Q-107 for the cost.
- Companies whose careers are not on Workday are out of scope here (Q-109):
  Dell (Workday site answers HTTP 422; careers appear to have moved to
  Oracle HCM), Qualcomm (left Workday; its old site answers 0
  postings), NetApp (site name not found, HTTP 422), and Lockheed Martin,
  L3Harris, UnitedHealth Group, Citi, AMD, Texas Instruments, Honeywell and
  ExxonMobil (no public Workday site found). Boeing and NVIDIA already have
  company plugins (`boeing`, `nvidia`).
- Adobe's `external_university` site answers HTTP 403 to anonymous requests
  and is not used.

## 4. Contracts

- `Site.<KEY> = '<key>'`, `category: 'company'`, `companyDomains` = the
  company's corporate domain(s), so `companyDomain` routing (Spec 5086) reaches
  the plugin — including where the domain-derived token differs from the key
  (`analog.com` → `analogdevices`, `t-mobile.com` → `tmobile`, `jnj.com` →
  `jnj`, `workday.com` → `workdayinc` rather than the ATS `workday`,
  `wbd.com` → `warnerbrosdiscovery`, `modernatx.com` → `moderna`,
  `gm.com` → `generalmotors`, `expediagroup.com`/`expedia.com` →
  `expediagroup`).
- Delegation contract, id rewrite (`wd-{tenant}-` → `<key>-`), diagnostics and
  tags exactly as Spec 1735 §4.2–4.3; tags `segment=workday-enterprise` plus
  the industry.
- Every caller input except `auth` passes through (Spec 1735 §4.5), so list
  mode (no keyword) returns the board's newest postings and keyword mode
  returns Workday's own keyword matches, up to `resultsWanted` per plugin.
- `companyName`: a posting's own Workday hiring organisation is kept when it
  names a business unit (RTX → Collins Aerospace, Pratt & Whitney, Raytheon);
  empty, tenant-token and legal-form names are re-stamped to the display name
  (Spec 1735 §4.2.1).

## 6. Test plan

Each plugin has a generated suite (Spec 1735 §5) run against the **real
Workday adapter** with mocked HTTP serving the recorded listings:

- registration: DI through the module, the `Site` value, the decorator
  metadata (category, domains, tag);
- recorded board: every recorded posting mapped, ids `<key>-<requisition id>`,
  site and company name re-stamped (the fixture's organisation label is the
  tenant, so only the re-stamp can produce the display name), only the
  recorded URLs requested, `resultsWanted=1`, a 404 board resolves with
  `bad_input`;
- delegation contract: board slug and caller input forwarded untouched,
  absent `resultsWanted` stays absent, only the leading prefix rewritten,
  `resultsWanted=0` makes no request;
- resilience: `not_registered` (no registry / no Workday), a failing board's
  reason surfaces, a benign `empty` passes through, a thrown error is
  classified;
- Visa only: boards in order with the remaining budget, stop once filled,
  cross-board de-duplication, partial outage keeps the healthy board's jobs.
- review follow-ups (Spec 1735 §4.2.1, §4.5): a caller's `auth` is never
  forwarded; a posting whose Workday hiring organisation names a business
  unit keeps that name through the real adapter; empty, tenant-token and
  legal-form names read as the display name.

The adapter suite (`source-ats-workday`) pins the politeness contract: never
more than one detail request in flight, a paced sleep before each detail
request, and `searchText` = the trimmed `searchTerm` (`''` in list mode).

## 7. Release and deploy ordering (merge gate)

The consumer (ever-hust) currently keeps only page 1 (80 jobs) of a response
that `JobsService` sorts **by site name**. `3m` sorts before every existing
site (`4earth_tech`, `abbvie`, …) and its board lists ~700 postings, so if
this batch reaches the deployment before the consumer ingests full results,
the consumer's page 1 fills with 3M postings first (today it is 66% AbbVie).
Sending the keyword to Workday (T6) narrows keyword searches to 3M's own
matches, but a keyword-less call would still lead with 3M.

**Gate:** deploy this batch only after the consumer's full-result ingestion
(NDJSON stream or all pages) is live. If it must ship earlier, hold the batch
out of the deployment with the existing kill switch — no code change, one env
line — and remove the line once the consumer is live:

```
EVER_JOBS_DISABLED_SOURCES=salesforce,adobe,intel,hp,hpe,mastercard,paypal,capitalone,walmart,target,northropgrumman,boozallen,caci,gdit,leidos,blueorigin,redhat,motorolasolutions,stryker,jnj,philips,mckesson,workdayinc,micron,analogdevices,tmobile,comcast,disney,nike,fidelity,statestreet,blackrock,autodesk,zillow,expediagroup,3m,rtx,humana,cvshealth,chevron,visa,geaerospace,wellsfargo,snap,morganstanley,copart,coxenterprises,broadcom,pfizer,marvell,generalmotors,warnerbrosdiscovery,moderna,gresearch,arrowstreetcapital
```

(the 53 plugins here plus the two Workday-backed quant plugins of Spec 1737;
append to any existing value). The list was checked against the source on
2026-09-25: it is exactly the 55 plugins whose service delegates to
`Site.WORKDAY`. Disabling them leaves the `workday` adapter itself
registered.

Fan-out order already matters: the fan-out deadline applies today (120 s by
default, `EVER_JOBS_SEARCH_DEADLINE_MS`; contract C4 renames it), and these
plugins are registered at the tail, so in a default fan-out that overruns it
they are the first sources skipped or abandoned mid-flight. Sequential detail
enrichment (T8) makes each Workday board slower, so a full sync that needs
them should select them explicitly or raise the deadline (Q-107 follow-up 2).
