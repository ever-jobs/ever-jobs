## 1. Problem Statement

`source-ats-smartrecruiters` mapped every posting with

```ts
const jobUrl = job.ref ?? `https://jobs.smartrecruiters.com/${companySlug}/${job.id}`;
```

`ref` is not a page. The public Posting API returns it as the posting's **API resource**:

```text
GET https://api.smartrecruiters.com/v1/companies/AbbVie/postings?limit=2      (live, 2026-09-25)
  content[0].ref        = https://api.smartrecruiters.com/v1/companies/AbbVie/postings/3743990015679966
  content[0].postingUrl = (absent)    content[0].applyUrl = (absent)    content[0].jobAd = (absent)
```

`ref` is always present, so the public fallback never ran and **every** SmartRecruiters
posting — plus every one of the 217 company plugins that delegate to this plugin — carried
a JSON URL as `jobUrl`. A downstream app builds its Apply link as
`applyUrl ?? jobUrl ?? jobUrlDirect`; 5,032 of its stored rows sent people to raw JSON.

The tests could not see it. All 217 delegating plugins' fixtures (651 postings, generated by
`scripts/scaffold-smartrecruiters-company-source.ts`) had a fabricated `ref` equal to the
public page, and asserted `jobUrl === first.ref`. The plugin itself had only a live e2e spec.

The detail endpoint does carry the public links:

```text
GET https://api.smartrecruiters.com/v1/companies/AbbVie/postings/3743990015679966   (live)
  postingUrl = https://jobs.smartrecruiters.com/AbbVie/3743990015679966-head-of-ai-transformation-…
  applyUrl   = https://jobs.smartrecruiters.com/AbbVie/3743990015679966-head-of-ai-…?oga=true
  ref        = (absent)

GET https://jobs.smartrecruiters.com/AbbVie/3743990015679966                          (live)
  200 text/html, 124,635 bytes — the id-only public pattern resolves without the slug
```

## 2. Decisions

- **D-01 — `jobUrl` is the public posting page.** First the API's `postingUrl` (detail
  shape), refused if it is API-shaped (`firstPublicUrl`, Spec 1751); otherwise
  `https://jobs.smartrecruiters.com/<companyIdentifier>/<postingId>`, which was verified live
  to serve the page.
- **D-02 — The identifier the API returned, not a guess.** `company.identifier` is
  case-sensitive (`AbbVie`); the caller's slug may be `abbvie`. Order: `company.identifier`
  → the `/companies/<Co>/` segment of `ref` → the caller's `companySlug` as given.
- **D-03 — `applyUrl` only from the API's `applyUrl`.** The list endpoint has none, so list
  postings get `applyUrl: null`; nothing is invented.
- **D-04 — `ref` is read, never linked.** It remains the fallback source of the posting id
  and company identifier. `JobPostDto` has no raw/metadata field, so the API URL itself is
  not kept anywhere.
- **D-05 — One posting id everywhere.** `id` (`sr-<id>`), `atsId` and the `jobUrl` path use
  the same id (`job.id`, else parsed from `ref`). A posting with no id at all is skipped
  instead of producing `…/undefined`.
- **D-06 — Fixtures mirror the live shape.** The 217 delegating plugins' fixtures now carry
  the real API-form `ref`, their tests assert the public pattern built from
  `company.identifier` + `id`, and the scaffold emits both — so a regression goes red in
  218 suites, not zero.

## 3. Non-goals

- Fetching the detail endpoint per posting. The list endpoint carries no `jobAd`, so list-
  mapped postings have no description today either — a separate, pre-existing gap recorded
  as **Q-111**; the scaffold's fixtures still fabricate a list `jobAd`.
- Rewriting rows already stored downstream. The mapping is deterministic
  (`https://api.smartrecruiters.com/v1/companies/<Co>/postings/<id>` →
  `https://jobs.smartrecruiters.com/<Co>/<id>`), but a downstream store that keys on
  `jobUrl` will see new URLs for existing postings and must migrate or re-key.

## 4. Acceptance

- A list posting (API `ref`, no `postingUrl`) maps to
  `https://jobs.smartrecruiters.com/AbbVie/<id>`, including when the caller passed `abbvie`.
- A detail-shaped posting maps `jobUrl = postingUrl`, `applyUrl = applyUrl`.
- An API-shaped `postingUrl`/`applyUrl` is refused.
- The authenticated (`X-SmartToken`) path maps identically.
- No `jobUrl` produced from any fixture contains `api.smartrecruiters.com`.
- Reintroducing `job.ref` turns the plugin suite, the delegating suites and the Spec 1751
  guard red.
